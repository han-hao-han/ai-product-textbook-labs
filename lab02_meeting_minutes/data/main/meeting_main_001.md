## 会议转写

王芳：今天我们过一下人工智能客服 MVP 上线前的进度。会议目标是确认知识库、接口联调、前端页面、测试计划和上线风险。先从知识库开始。

张琳：知识库清洗已经完成第一轮，FAQ 里有 126 条重复问法已经合并。现在还剩退款、发票、物流三个场景的标签没有完全统一，主要问题是“退款进度”和“退款到账时间”容易被标成同一类。

王芳：知识库标签这块本周必须收口。张琳，你在本周五前完成退款和发票场景的标签复核，把需要产品确认的样例整理出来。

张琳：可以，我本周五前给出复核表。物流场景我建议先保留现有标签，等灰度数据回来再看。

李明：接口联调方面，订单查询和物流查询已经打通，退款接口还有一个异常码没有对齐。支付系统那边今天上午刚给了新说明，我需要再改一次映射。

王芳：那退款接口联调先定下来，李明在下周三前完成退款接口异常码映射和联调验证。这个会影响测试进入完整流程。

李明：没问题。还有一个点，人工转接接口现在只返回转接是否成功，不返回转接原因。如果要做满意度标签分析，后端需要新增字段。

王芳：满意度标签这件事先不做决策。我们需要确认上线首版是否真的要接入人工转接原因，否则会影响范围。

陈晨：前端页面这边，客服工作台的会话列表和答案推荐卡片已经完成。风险提示弹窗还差一个交互确认，主要是不确定高风险答案是不是必须二次确认。

王芳：前端先按二次确认方案实现。陈晨，你在下周三前补齐风险提示弹窗，并把确认按钮和取消按钮的埋点事件加上。

陈晨：可以。埋点字段我需要产品给一个命名表，不然我怕和数据看板对不上。

王芳：埋点命名表由我来整理，我明天下午发给陈晨和李明。

赵强：测试计划已经写完主流程，包括订单查询、物流查询、退款咨询和发票咨询。阻塞点是退款接口还没好，所以完整回归要等李明那边完成。另一个问题是知识库标签变更后，历史测试用例要更新。

王芳：测试这边按两步走。赵强本周五前先完成订单、物流、发票三个场景的回归测试；退款场景等接口联调完成后再补测。

赵强：可以。历史测试用例更新需要有人把标签变更清单同步给我。

张琳：我可以在复核表里加一列“影响测试用例”，但具体怎么改测试步骤需要测试同学判断。

王芳：那就这样，张琳在复核表里增加影响测试用例说明，赵强根据复核表更新测试用例。

李明：上线安排方面，运维同事问过是否要周五晚上灰度。如果退款接口下周三才完成，周五灰度会比较紧。

王芳：上线时间今天不定。我们先保留“下周五前完成灰度准备”的目标，但是否下周五晚上灰度，要等退款接口和回归结果出来后再决定。

陈晨：还有一个前端问题，移动端客服入口的样式没有验收，但 MVP 首版是不是只覆盖 Web 工作台？

王芳：这个形成决策：MVP 首版只覆盖 Web 客服工作台，移动端客服入口不进入本次上线范围。

赵强：那我测试范围也按 Web 工作台来写，移动端只记录为未覆盖范围。

王芳：好的。最后补充一个待办，灰度上线前需要准备客服培训说明，但今天没有确定负责人。这个事项先记下来，下一次项目会上明确谁负责。

王芳：我总结一下：知识库本周五收口，退款接口下周三完成，前端风险弹窗下周三完成，测试先做三个已通场景，MVP 首版只覆盖 Web 工作台。人工转接原因字段和下周五是否灰度上线仍待确认。

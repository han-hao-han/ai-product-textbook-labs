## 更新后的隐私边界

用户于 2026-07-23 明确：

```text
身份证号码：不得出现在原图或标注中，命中即排除
姓名：允许出现，不作为排除条件
电话、地址、账号等其他信息：不自动排除，但必须记录并人工复核
```

自动扫描只能检查标注文本；“未命中”不代表原图一定没有身份证号码。正式样本仍须逐张看图。

## 方案一：重新筛选 XFUND

官方仓库：

- <https://github.com/doc-analysis/XFUND>
- <https://github.com/doc-analysis/XFUND/releases/tag/v1.0>

官方说明确认：

- 数据包含中文在内的 7 种语言；
- 表单由人工标注，含实体和关系；
- v1.0 可从 GitHub Release 直接下载，不要求学生提交申请；
- 项目内容采用 CC BY-NC-SA 4.0。

本地实际审计结果：

```text
中文训练文档：149
身份证号码模式硬排除：78
未被硬排除且具备图像与参考字段：71
```

这 71 张只是候选池，不是已经通过隐私检查的样本。正式重选必须：

1. 从候选池生成本地查看页；
2. 逐张检查原图是否出现完整或局部身份证号码；
3. 同时检查标注是否遗漏了原图中的身份证号码；
4. 记录其他隐私类别，但姓名不再导致淘汰；
5. 重新冻结 1 张主样本、3 张观察样本和 6 张验证样本；
6. 不依据模型识别效果选样。

优点：

- 保持中文真实表单主线；
- 无需学生申请；
- 现有下载、转换、候选、比较和界面代码可继续复用；
- 只需重开 H2，不必立即把实验改造成另一种语言或另一类任务。

限制：

- 原始人工标注可能存在错误；
- 必须启用“原始标注 + 人工复核 + 人工校正记录”的参考结果流程；
- 不能再沿用此前按旧隐私规则选定的样本。

## 方案二：CORD v2

官方来源：

- <https://github.com/clovaai/cord>
- <https://huggingface.co/datasets/naver-clova-ix/cord-v2>

已核验事实：

- 数据来自真实印尼商店和餐馆票据；
- 公开版本有 1,000 张图片，划分为 800/100/100；
- 包含 OCR 框、文本、层级语义标签和结构化 `gt_parse`；
- CORD v2 修正了已知错误标签；
- 采用 CC BY 4.0；
- 可以直接从 Hugging Face 获取，不要求身份申请；
- 发布方因当地法律问题移除了 `store_info`、`payment_info` 和 `etc` 等目标类别。

在线预览的前 26 条标注中，未检出 `NIK`、`KTP` 或连续 16 位数字模式。该结果只是小样本标注预筛，不能代替下载后的全量原图与标注检查。

主要代价：

- 实验将从“中文表单”改成“印尼语票据”；
- 教学重点会从开放式 question-answer 关系转为预设票据字段；
- Prompt、Schema、参考结果转换和教材标题都需要重做。

因此，只有在用户接受跨语言票据实验时，CORD v2 才优于重新筛选 XFUND。

## 其他候选为何不优先

### FUNSD

官方页面：

- <https://guillaumejaume.github.io/FUNSD/>
- <https://guillaumejaume.github.io/FUNSD/work/>

FUNSD 有 199 张真实英语扫描表单和完整实体关系标注，且可直接下载。但官方条款要求使用者年满 18 岁，只允许非商业研究与教育用途，并明确提示原图来自 RVL-CDIP、使用者需自行判断额外的图片授权。它不适合作为面向所有学生的低门槛默认数据。

### EPHOIE

官方仓库：

- <https://github.com/HCIILAB/EPHOIE>

EPHOIE 是 1,494 张真实中文试卷页眉，姓名和学校经过擦除与重合成，也提供 OCR 和实体标注。但官方要求填写申请表、发送论文信息、经审批后取得解压密码，仍然存在与 SCID 相同的学生获取门槛。

### WildReceipt

官方数据配置：

- <https://github.com/open-mmlab/mmocr/tree/main/dataset_zoo/wildreceipt>

它可以直接下载并支持 KIE，但官方元数据把许可证写为 `N/A`，不能满足本项目“许可清晰”的准入条件。

### EATEN/PICK 火车票

官方仓库：

- <https://github.com/beacandler/EATEN>
- <https://github.com/wenwenyu/PICK-pytorch>

公开版本混合大量合成图和少量真实火车票；实名火车票又天然可能出现身份证号码。它既不满足“真实数据优先”的主线，也不适合当前身份证号码硬排除规则。

## 建议的 H1 决策

推荐采用：

```text
保留 XFUND 作为数据源
＋将隐私硬排除收敛为身份证号码
＋从 71 张候选中重新人工选定 10 张固定样本
＋为每张样本保存隐私复核和人工标注校正记录
```

若用户不接受 XFUND 原始标注质量，则第二选择是 CORD v2，但需要明确同意把实验改为跨语言票据结构化识别。
